> [用户材料] 003 直播 P3 约11–77 min，以访问网站和2021年第47题串联 DNS、ARP、交换机、路由器。老师特别强调域名树形组织与物理网络拓扑不是一回事。

## 一、DNS 为什么必要？

应用程序常用容易记忆的域名（如 `www.example.com`）标识服务器，但网络层转发 IP 数据报需要目标 IP 地址。DNS 负责其中的名称解析，例如查询某域名对应的 IPv4 地址；获得 IP 后，主机才可按相应应用协议与目标通信。

本地/默认 DNS 服务器的 IP 可以由 DHCP 提供，也可以由用户或系统按需指定。这里的“本地”指客户端通常向它发起递归查询的角色，**不等于它必定和客户端在同一个物理局域网或子网**。

先检查已知映射和缓存。若缓存存在且有效，可能直接用已有结果，不需要每次都重新访问各级服务器。未命中时才进入域名解析的相应流程。

## 二、逻辑域名树与各级服务器

```text
用户主机 → 本地 DNS（缓存或代办查询）
                   │ 未命中
                   ▼
              根域名服务器 ─── 指向相关顶级域服务器
                   ▼
              顶级域服务器 (.com/.cn/等) ─── 指向权限服务器
                   ▼
              权限域名服务器 ─── 本域的资源记录/委派
```

例如课程以 `www.dddd.com` 为服务名、`.com` 为顶级域，相关权限 DNS 保存该域名的记录。服务器可属于不同机构，分布在互联网各地，域名体系的逻辑管理树并非服务器之间的物理线路树。根域服务也不能机械理解为全球仅存在13台物理机器；根服务器存在逻辑命名/实例化等区分。

### 老师的宿舍类比

要打听某个同学住在哪间宿舍，先找消息灵通的舍友（本地 DNS）。如果他不知道，可以问校长（根），再找到对应学院（顶级域）和院系负责人（权限 DNS），最后获得地址。若舍友已经缓存了这个消息，就不必再逐级询问。

## 三、递归查询与迭代查询（必分）

| 方式 | 某服务器若不知道答案 | 谁继续查找 |
|---|---|---|
| 递归 | 帮查询者继续向其他服务器寻找，直到返回答案或失败 | 被问者代办 |
| 迭代 | 提供下一步可去询问的服务器或相关记录 | 发起者自己继续询问 |

记忆：递归像帮人跑腿，迭代像为人指路。实际课堂常见情形是主机请求本地 DNS 代办，后者在缓存未命中时迭代咨询根/顶级/权限服务器，取得结果后返回主机。题目给出不同过程时，按实际所画的查询方式计算通信次数或时延。

## 四、DNS 封装与端口

课程典型 DNS 查询用 UDP，服务器熟知端口53。设客户端临时端口 p：

| 项目 | 查询 | 响应 |
|---|---|---|
| UDP 源端口 | p | 53 |
| UDP 目的端口 | 53 | p |
| IP 源地址 | 客户端的 IP | DNS 服务器的 IP |
| IP 目的地址 | DNS 服务器的 IP | 客户端 IP |

查询响应的端口不是任意重选一个端口，必须到达原请求对应的客户端端点。不要把 DHCP 的 UDP 68/67 端口套到 DNS；客户端临时端口通常由系统选择。部分 DNS 交换也可使用 TCP，典型题若明确 UDP 则按 UDP 封装。

实际发送前，主机以本机掩码判断 DNS 的 IP 是否同子网。如果同网，通过 ARP（缓存未命中时）解析 DNS 自身 MAC；如果跨网，则解析默认网关的 MAC，**IP 目的仍是 DNS 服务器**，帧目的只指向就近下一跳路由器。

## 五、2021 年第 47 题的分步骤思路

课例为 H1 通过域名访问互联网中的 Web，初始 ARP 表与交换表为空（按题设时间区间判断）。局域网内：H1 为 `192.168.1.2/25`，MAC 尾部 cc、连接交换 S 端口4；H2 为 `.3/25`，尾部 dd、端口3；DNS 为 `.126/25`，尾部 bb、端口1；网关 R 为 `.1/25`，尾部 aa、端口2。它们同属 `192.168.1.0/25`。

![DNS、网关、交换机与外网Web的拓扑](/408-network-notes/assets/network/6.2-DNS-HTTP-ARP综合题.jpg)

1. 查 DNS 的 IP 与本机网络前缀相同，H1 如无 DNS MAC 缓存需 ARP 请求；广播帧使交换机学习源 H1 的端口，DNS 单播响应使交换机学习 DNS 入口。
2. 发送 DNS 查询，服务器返回目标 Web 的 IP。此过程的目的 MAC 是本地 DNS，不是外网 Web。
3. 取得 Web 地址后再判断是否同网。本题 Web 在 Internet，下一跳取默认网关；必要时发 ARP 解析其 MAC。若使用常规 HTTP/TCP，应先建立相应传输连接再发 HTTP 请求。

若物理层设备把收到的信号转发到其他主机，不意味着这些主机的应用层也收到 DNS 响应。网卡根据目的 MAC 等接收条件筛选，网络层和 UDP 再按目的IP/端口递交。老师反复提醒考题往往将“收到帧、接收数据报、交给应用”作为不同层次。

## 重点清单

- DNS 解析的是域名→相关资源记录（典型为IP）；本地 DNS 不一定物理同网。
- 缓存、根/顶级/权限服务器各自角色以及逻辑层级与真实拓扑的区别。
- 递归=代办，迭代=指路。
- 常规查询 UDP 目的53；响应源53、目的原客户端临时端口。不是 DHCP 67/68。
- 同子网 ARP 目的主机；跨子网 ARP 网关，目的IP仍保持最终端点。结合2/3/4层逐层判断是否真正递交。
