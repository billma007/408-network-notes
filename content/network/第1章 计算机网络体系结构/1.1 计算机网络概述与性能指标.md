# 1.1 计算机网络概述与性能指标（强化课计算工具）

> [用户材料] 001 P1 各介质和卫星链路、003 HTTP 时延、007 2022/2025题。强化课没有独立重讲第一章所有基础定义，本节汇总实际贯穿的计算工具。

## 一、网络连接与带宽

老师以荒岛场景串联：两台主机可先通过物理介质相连；再用集线器/交换机扩为局域网；路由器互连IP网络；远端 ISP 和卫星链路再将局域网接入互联网。真正端到端应用通信涉及各层，不能因某部件在物理层处理信号就称其进行IP路由选择。

物理信道的频率带宽 W 用 Hz 衡量（奈奎斯特、香农）；网络链路数据传输速率常用 bit/s，实际吞吐还受到线路限制、协议开销、窗口和错误恢复等影响。老师类比“木桶效应”，多个串接链路时长期理想吞吐一般受最慢一条限制，并非把每条链路速率相加。

## 二、四类时延与 RTT

| 时延 | 含义 | 常见计算 |
|---|---|---|
| 发送时延（传输/串行化） | 将整个数据的比特推入链路 | $L/R$，L用bit，R用bit/s |
| 传播时延 | 信号沿实际物理距离到达对端 | $D/v$ |
| 处理时延 | 节点处理包头、判断、信号转换等 | 按题设 |
| 排队时延 | 等待处理及链路资源 | 按题设 |

发送时延与传播时延可共同决定最后一位到达的时刻。对于卫星这样距离长而线路可能比端侧网络慢很多的链路，首帧数据发送后仍需等待单向传播，ACK还需传播返回。题中 RTT 如特指纯往返传播则 $2D/v$；若 RTT 已含协议其它延迟就不能把同一项重复相加。

2025例：单向卫星传播两段共72000km、300000km/s→0.24s，200kb/s发送4000B需0.16s，主要端到端最短约0.40s，不应仅算0.16。若要知道停等/滑动窗口下有效吞吐，继续按窗口计算（3.4）。

## 三、单位与题意（考前必查）

- bit/b 与 byte/B 不同，8 bit=1B。
- 网络速率标称kb/s、Mb/s常用10的幂，题中KB若指定K=1024要遵照；不要将200kb/s误读成200KB/s。
- 1s=1000ms=1,000,000µs；时间除以时间同单位后才得利用率。
- 计算“吞吐率”往往看成功数据量/总耗时；帧中有效数据量和总帧长度未必相等。利用率不得超过100%。
- HTTP题“小图像/忽略传输时延”意味着给定模型可以只数RTT；大文件、ACK时间或转发额外开销须以题设决定。
