# 6.1 网络应用模型与常用协议

> [用户材料] 002–005 逐层封装、DNS、HTTP、FTP 与各协议端口清单，007 结课解析。本节归纳直播所用的客户端—服务器模型及各协议归属，未单独重讲基础课的全部应用模型。

计算机网络最终是为了应用进程之间交换消息。常见课例为客户端发请求、服务器提供服务（例如浏览器访问 Web、主机询问 DNS）。IP 找的是主机/网络接口，传输层端口再找到运行在主机上的相应应用进程。客户端、服务器是进程在特定通信中的角色，不代表设备物理上必须使用某种特定硬件。

## 一、端口速记表（强化课明确列为考前回顾）

| 应用/相关协议 | 传输或直接承载方式 | 典型熟知端口 | 作用 |
|---|---|---|---|
| HTTP | TCP（本课程典型 HTTP/1.x） | 80 | 浏览器请求 Web 资源 |
| DNS | 通常 UDP查询，也可 TCP | 53 | 名称解析 |
| FTP | TCP | 21 控制；20 主动数据 | 文件传输，两条不同连接 |
| SMTP | TCP | 25 | 邮件提交/服务器间推送（课程典型模型） |
| POP3 | TCP | 110 | 客户端收取邮件（拉取） |
| DHCP | UDP | 服务器67，客户端68 | 动态分配地址等参数 |
| RIP | UDP | 520 | AS内部距离向量路由选择 |
| BGP | TCP | 179 | AS间路由可达性通告与策略选择 |
| OSPF | 直接承载于IP，协议号89 | 无TCP/UDP端口 | 链路状态、AS内部路由 |
| ICMP | 直接承载于IP，协议号1 | 无TCP/UDP端口 | 网际控制和差错报告等 |
| ARP | 直接承载于以太网帧，类型0806H | 无TCP/UDP端口 | 本地链路IP→MAC |

熟知端口是课例中服务进程的通常端口，普通客户端的源端口常为临时值，响应的目的端口要对应原发起端点。DHCP 初次配置客户端68与服务器67是特例。老师要求区分 RIP、BGP 虽承担网络层路由选择功能，其协议通信报文却使用 UDP/TCP；OSPF 不套 TCP/UDP。

DNS 不宜记作“只能UDP”：课堂普通查询以UDP为主，也可以采用TCP（例如一些大型响应或区域传送），具体行为按题设。HTTP 表中的TCP/80同样指课程传统模型，不把其他现代协议变体强行带入真题。

## 二、消息与服务的层次

应用层报文可能很小（一次 DNS 查询），也可能很大（包含大型 HTTP 上传内容）。应用层自己决定请求、应答、格式与业务含义；传输层提供相应端到端传送；IP 处理网络交付；每一跳用适合该链路的帧格式封装。有关长度和头部字段的综合计算见1.2、4.2、5.2、5.3。

## 重点清单

- 熟知端口和承载方式成对记忆；重点区分DHCP67/68、DNS53、FTP21/20、SMTP25、POP3 110。
- ARP直接封装到链路帧，ICMP、OSPF直接承载于IP；RIP用UDP，BGP用TCP。
- 应用通信角色与物理设备或协议分层不同：先看业务，再依各层标识和协议实际转发。
