> [用户材料] 003 直播 P3 约119–166min、004 的报文封装例、007 2011年第47题及结课变式。老师强调真正要数的是资源数、连接数与题目指定的起算点，不能死背 RTT 个数。

## 一、从输入域名到接收网页

1. DNS 将目标域名解析为 IP（可能已有缓存）。
2. 主机判断是否同子网；跨网先解析网关MAC（若ARP未命中）。
3. 在课程经典 HTTP/1.x 模型中，若没有可复用连接，浏览器与目标 Web 进程建立 TCP 连接（典型熟知端口80）。第三次握手可能携带应用数据；题设要求纯握手时按题给时序。
4. 发送 HTTP 请求，例如 GET 某HTML文件。服务器响应原请求的资源。
5. 浏览器解析 HTML 后，才知道它所引用的图片、脚本、样式等资源地址，再发送相应请求。获取首页HTML不是已经获取网页所有资源。

老师强调经典考题一份请求通常对应一个所请求的资源；若HTML另引用 k 个小资源，则至少需要考虑1+k份相应请求，不是 k 份。

## 二、HTTP 消息的结构

```text
请求：请求行（方法、目标路径、版本）
      首部行（如Host等）
      空行
      可选请求实体/消息体

响应：状态行（版本、状态码、说明）
      首部行
      空行
      可选响应实体
```

GET 常用于请求资源，POST 可提交实体（课堂以图像上传为例）。请求/应答的应用层格式与 TCP 段首部不是同一种首部。大 HTTP 报文若分成多个 TCP数据段，**HTTP 首部和请求行逻辑上只有一份**，不应为每个TCP段复制HTTP头。

传统HTTP本身无状态，Cookie等机制可在应用交互中帮助关联状态。端口80是课堂典型普通HTTP服务；识别题中若给具体版本/其它服务以题意为准。

## 三、四种 HTTP 连接与请求模式（重点时延题）

以典型老教材 HTTP/TCP 模型，忽略DNS、处理时延、传输文件的发送时延，RTT仅按题设请求往返；客户端开始时还没TCP连接。一个首页HTML，之后引用 k>0 个可同时得知URL的小资源。假定连接建立1RTT、一个HTTP请求/响应1RTT：

| 方式 | 首页 | 后续 k 个资源 | 总时间（从未建连接开始） |
|---|---:|---:|---:|
| 非持续、串行 | 2RTT | 每个单独TCP+请求响应，2kRTT | $2(k+1)RTT$ |
| 非持续、全并行（题设足够连接数） | 2RTT | 同时建 k 条连接，2RTT | 4RTT |
| 持续、非流水线 | 2RTT | 复用连接，逐个请求返答，kRTT | $(2+k)RTT$ |
| 持续、流水线 | 2RTT | 已知全部资源后连续发请求，理想1RTT | 3RTT |

若 k=0 的纯首页，各方式在未连接时均为2RTT。若题目从 TCP 已建立且**首次 GET 已发出**起算，所有上述时间减去第一次建立连接的1RTT。真实并发数量、传输调度、丢包等待或现代HTTP机制可能改变时序，应依题给模型。

页面在最后所需资源到达后即可准备显示，通常不需等所有 TCP 四次挥手和TIME-WAIT结束；除非题目明确问完成连接关闭的时间，否则不能额外机械加2RTT。题中若说“小图片”“忽略短文件传输”，才可把发送时间置为0；否则响应文件 L bit 在带宽R上有相应 L/R 时间，并行方式还须考虑共享瓶颈与发送次序。

## 四、2011年第47题：拆报文、ARP与HTTP时延

题中给出一份发往Internet的 Web 请求以太网帧头部的十六进制内容。老师提示按“662N4”和 IP/TCP 首部长逐层定位：典型以太网首部14B（FCS在尾），IPv4首部由IHL确定，TCP首部由Data Offset确定。不能无脑把18B以太网总开销全算作帧首部。

课件核对的数据：目的MAC `00:21:27:21:51:CE` 为同网默认网关 MAC；源IP `10.2.128.100` 私网；IP目的 `40 AA 62 20` → `64.170.98.32`，是Web服务器；IP总长 `01EFH`=495B。EtherType0800H为IPv4，IHL5=20B，TCP Data Offset5=20B，目标端口0050H=80。GET内容从偏移54B（0x36）处开始。题中帧只是截取前80B，不意味着整帧只有80B。

主机先通过 ARP 找默认网关 MAC；ARP 请求封装为广播 MAC 全1。跨NAT后，问 **IP首部**变化应注意源IP、TTL与IP首部校验和；端口属TCP头不在此问范围。

第三小问：一个已发出的GET请求获取首页，另引用5个小JPEG图像；题从该GET**发出时**开始，不再算第一次TCP连接建立。HTTP持续非流水线为1+5=6RTT。老师扩展四种模式：此起点下非持续串行11RTT、非持续并行3RTT、持续流水线2RTT。若改为从完全未建 TCP 起则分别再加1RTT。

## 五、HTTP 大文件的跨层计算

004例中HTTP POST总消息3200B（头部200B、图像3000B），MSS1460且无IP/TCP选项，TCP净荷分1460、1460、280B；每段TCP头20B→TCP总长1480、1480、300；IPv4总长1500、1500、320；典型以太网MAC帧1518、1518、338。没有IP分片。这是**TCP分段**不是IP分片，只有一个原应用报文的HTTP首部；接收方TCP按SEQ恢复完整字节流再交应用。若源方向初始序号500，第一数据段seq501，其余seq1961、3421，全部接收ACK3701。

## 重点清单

- 一个首页+k个引用资源对应1+k份请求；后一批请求需要先解析首页。
- 持续/非持续决定连接是否复用；流水线/非流水线决定是否可在同一连接连续发送请求。
- 先在时间线上标定题目起算点（是否已完成握手/已发送GET），再数RTT；只问网页到达时不擅自加挥手时延。
- “小文件”通常指发送时间可忽略；大文件另计。分层拆报文先定可变首部长，HTTP首部不随TCP分段重复。
