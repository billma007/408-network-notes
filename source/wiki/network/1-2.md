## 一、五层各自做什么

| 层 | 课程典型数据单位/标识 | 主要任务 |
|---|---|---|
| 应用层 | HTTP/DNS/FTP/DHCP等报文 | 具体应用业务和消息格式 |
| 传输层 | TCP报文段、UDP用户数据报；端口 | 进程间传输、相应可靠/无连接服务 |
| 网络层 | IP数据报/分片；IP地址 | 根据目标网络/路由表转发、选择路径 |
| 数据链路层 | MAC帧、链路地址 | 本次链路交付、帧长度、介质访问等 |
| 物理层 | 比特/物理信号、码元 | 在介质上传递信号并恢复比特 |

交换机主要工作在链路层，普通路由器主要处理网络层及以下；NAT/PAT还处理传输层端点字段。不要把应用协议在图上靠近路由器理解成它就不使用运输层。各层的**标识解决的问题不同**：域名（应用习惯）→IP（最终端点/路由）→下一跳MAC（链路）以及端口（进程）。

## 二、逐层封装与跨节点是否变化

```text
HTTP应用报文
     ↓ TCP首部 + 按MSS形成的数据段（或UDP首部+完整应用消息）
TCP段 / UDP数据报
     ↓ IPv4首部（超出出接口MTU时按规则分片）
IP数据报或分片
     ↓ 本链路的MAC帧首尾、必要填充
比特流/场上的物理信号
```

普通二层交换机按源 MAC 学习、按目的 MAC 转发；普通路由器拆本跳链路帧，查询目标 IP，TTL−1并处理IPv4首部校验和，再按出链路重新封装。无 NAT 等改写时端到端IP地址和端口通常不变；NAT出入方向要另外查映射。不同链路甚至可使用不同帧格式（例如手机→AP是802.11，AP→交换机是以太网），不能总用一个MAC地址或同一个帧头贯穿全程。

## 三、常用报文长度关系（课中默认无可变选项）

| 协议 | 首/尾长度、注意点 |
|---|---|
| UDP | 固定首部8B，UDP总长16位字段 |
| TCP | 基本首部20B，Data Offset以4B为单位，选项可使其更长 |
| IPv4 | 基本首部20B，IHL以4B为单位，Total Length是IP首部+数据 |
| 以太网 | 首部14B、尾部FCS4B、数据46～1500B（题未给其他额外字段） |

逐层封装不是无条件叠加四个常数，要先看室内链路、实际首部长、上层是否分段、IP是否分片、MAC是否需要填充。

### 课中训练（不分段、不分片的情况）

| 应用/运输报文 | 运输层总长度 | IPv4总长 | 以太MAC帧长 |
|---|---:|---:|---:|
| DNS消息40B，UDP | 48B | 68B | 86B |
| 纯TCP SYN，没有应用数据，TCP头20B | 20B | 40B | 64B（数据字段补6B至46） |
| GET HTTP 200B，TCP | 220B | 240B | 258B |

纯TCP SYN的40B IP 包填在以太网最短数据部分时，**IP总长仍然40**；额外6B链路填充不是IP净荷，接收端按IP总长度判断有效范围。若链路为课中802.11且帧主体最小0B，则不强制同样的6B填充。

## 四、分段、分片、填充三个过程不要混

| 过程 | 层 | 核心条件 |
|---|---|---|
| TCP分段 | 传输层 | 数据为字节流，依据MSS形成多个段，每段加TCP头并按字节编号 |
| UDP用户数据报 | 传输层 | 通常把一个应用消息加8B头形成一个完整UDP数据报，不像TCP按MSS分段 |
| IPv4分片 | 网络层 | IP包超过当前可用链路MTU且允许分片，拆原IP数据、各片加IP头，保持标识并给原始偏移 |
| 以太网数据填充 | 数据链路层 | 需承载的上层数据不足46B时补足，IP长度不变 |

例如典型以太网 MTU1500、无IP/TCP选项，MSS可取1500−20−20=1460B。3200B HTTP经过TCP可拆1460/1460/280三段，各包总长1500/1500/320，无需在该链路上IP分片。若3200B应用消息经UDP，原IP总长3228B，必须另按MTU及8B偏移单位做IP分片。细节在4.2和5.3。

## 五、封装层次的特例（老师要求列入记忆清单）

| 协议 | 实际承载方式 |
|---|---|
| ARP | 直接以太帧，EtherType0806H；不加IP/TCP/UDP头 |
| ICMP | 直接作为IP数据，IPv4 Protocol=1 |
| OSPF | 直接作为IP数据，Protocol=89 |
| RIP | UDP520（路由功能与其报文承载层次区别） |
| BGP | TCP179 |
| DHCP | UDP68↔67 |
| DNS | UDP53常见，也可TCP53 |
| PPP/PPPoE | 课堂作链路层及链路层封装例，具体帧格式以题意 |

**考试套路**：长报文十六进制拆解，先找MAC数据起点（典型偏移14B），读EtherType确认是IP还是ARP；若IPv4则用IHL定位上层，不假定IP一定20B；用Protocol区分UDP/TCP等，接着按UDP固定8B或TCP可变Data Offset找应用数据。不把题目提供的“前40B”“前80B”误当整份包的真实总长度。
