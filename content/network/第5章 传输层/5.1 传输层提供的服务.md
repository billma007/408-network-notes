# 5.1 传输层提供的服务

> [用户材料] 003 DNS/HTTP/FTP、004 分层封装、007 拆TCP报文与窗口题。

网络层 IP 将分组送往目标网络或主机，传输层则面向主机中的应用进程。源/目的端口与源/目的IP结合标识通信端点；同一主机可能同时运行多个使用网络的应用进程，应根据实际协议及端点递交对应消息。

| 对比 | UDP | TCP |
|---|---|---|
| 连接 | 无须事先建立常规传输连接 | 面向连接，建立/释放连接 |
| 上层数据 | 面向数据报/应用消息，不以MSS分段 | 面向字节流，按MSS等形成一个个段 |
| 可靠性 | 本身没有TCP式可靠服务，丢失可能由应用另行处理 | 有序可靠字节流、确认/重传等 |
| 流量/拥塞控制 | 本身不提供TCP式机制 | 接收窗口与拥塞窗口共同控制发送 |
| 最小/固定运输首部 | 8B固定 | 最少20B，可有选项 |

典型客户端临时端口 p → 服务端熟知端口（如 DNS53、HTTP80），服务器响应时源/目的方向交换，目的仍需要是对应客户端的 p。DHCP两端端口68/67为固定课例。NAT/PAT可映射内外网端口，不代表普通路由每跳改变运输端点。

老师提醒：不能从TCP可靠就直接推断所有应用都必须采用TCP；DNS小查询和DHCP初始无IP等在课中采用UDP；HTTP传统题和FTP数据连接需要相应TCP机制。各协议详细归类见6.1。

## 重点清单

- IP寻址主机/网络接口，端口识别应用进程；正常应答的源、目的端口与请求方向相反。
- UDP保留数据报边界，TCP提供可靠字节流；只有TCP采用这里讨论的MSS分段及双窗口控制。
- DHCP端口68/67，DNS常见UDP53但也可TCP；不要将路由协议的功能层次与其实际承载层次混为一谈。
