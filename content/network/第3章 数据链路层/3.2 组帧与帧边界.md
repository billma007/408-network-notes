# 3.2 组帧与帧边界（封装专项）

> [用户材料] 001 以太网帧、004–005 封装与无线帧。本套课实际重点为帧结构和长度，未独立展开比特/字符填充算法的专项例题。

组帧把需要交付的上层数据组织成有相应首尾和边界的链路层协议数据单位。具体格式取决于当前链路，不能沿途一直使用一种帧。

- 典型以太网MAC帧为6B目的MAC + 6B源MAC + 2B类型/长度 + 46～1500B数据 + 4B FCS（记忆“662N4”）。
- 以太网IP数据报不足46B时，链路层补到46B。IP总长仍表示有效IP数据报的长度，补齐字节不是IP净荷。题给前导码、起始定界符、帧间隙等，要区分MAC帧长度与物理线路占用时间。
- 802.11基本三地址帧首部24B；带第四地址的基本首部30B。其具体数据长度范围和帧首部以题设格式为准。

课中纯TCP SYN的例子：20B TCP头 + 20B IPv4头 = 40B IP数据报。以太网帧为14+46+4=64B；补6B发生在以太网数据字段中，不改IP总长，也不改变TCP的SEQ。无线链路若采用帧体最低0B模型，则不需要照搬以太网最小帧的补齐规则。

**重点**：区分IP分片、TCP分段与链路层填充；“帧在物理层的边界/透明传输”不等于“为满足以太网最小长度而补齐”。详细帧字段与802.11地址口诀参见[3.6](<3.6 局域网与以太网.md>)。
