## 一、先建立总框架

网络题最重要的思维：**先分层，再确定本次传输的对象，最后才计算字段。** 一次通信涉及多层地址和不同长度，不能把一个层次的量套到另一个层次。

| 层 | 传输单位、标识 | 典型设备/协议 |
|---|---|---|
| 应用层 | 消息、域名、应用请求 | HTTP、DNS、DHCP、FTP、SMTP、POP3 |
| 传输层 | TCP段/UDP数据报，端口号 | TCP、UDP；进程到进程 |
| 网络层 | IP数据报、IP地址 | 路由器、IP、ICMP、ARP（相关协议） |
| 数据链路层 | 帧、MAC地址 | 交换机、网桥、无线AP |
| 物理层 | 比特、信号、码元 | 中继器、集线器 |

- 交换机按源MAC学习、按目的MAC转发；路由器按目的IP和最长前缀匹配选下一跳。
- 一个普通路由器转发时：重新封装本链路帧，更新TTL、IPv4首部校验和；正常端到端源/目的IP与端口不变。经过NAT时才另做端点映射，发生分片时另更新分片有关字段。
- 典型完整流程：新主机通过DHCP取得配置 → 判断DNS服务器是否同网，必要时ARP解析下一跳 → DNS解析域名 → 判断Web服务器同网/异网 → ARP查所需下一跳（已有缓存就不查） → TCP握手 → HTTP交互；路由器逐跳转发，NAT按映射转换。
- 老师的“找人”理解：域名是想找的对象的名称，IP是网络位置，MAC是当前链路交付对象，端口是具体进程。不要拿远端服务器MAC当首跳地址。

## 二、单位、物理层与时延：算题先查这一页

| 量 | 记法 |
|---|---|
| 比特、字节 | 1B=8bit；速率b/s与B/s差8倍；网络线路K/M通常十进制，缓存KB题常按1024B，以题设为准 |
| 码元速率 | Baud（码元/s）；每码元V种状态，可承载log₂V bit |
| 奈奎斯特 | 理想无噪声低通信道，最多2W Baud，最大比特率2W log₂V |
| 香农 | 有噪声信道上限W log₂(1+S/N)；若给dB，S/N=10^(dB/10)；给线性比值不必转换 |
| 理论容量 | 题设同时受以上两种限制时，取两者较小值；老师称“两个天花板” |
| 发送时延 | L/R（L以bit计，R为bit/s） |
| 传播时延 | d/v；经过多段就求和，与包长无关 |
| 端到端时延 | 发送+传播+处理+排队，逐跳情况还看是否存储转发 |
| 吞吐率 | 最慢瓶颈限制整体，“木桶效应”；窗口及RTT可能进一步降低有效速率 |
| RTT | 往返时间。题目若已经含发送/处理，就不能再机械附加同一项 |

编码与介质：

- NRZ电平表示数据；曼彻斯特每位中间必跳，课程约定“上0下1，看中间”；差分曼彻斯特看每位开始有没有跳变（课例“跳0不跳1”），中间跳变用于同步。约定随题切换。
- ASK改变振幅、FSK改变频率、PSK改变相位、QAM组合振幅和相位；状态数决定每码元位数。
- 双绞线、同轴、光纤、电磁波各有介质和传播条件，不能把光在真空的速度直接套给全部网线。光纤抗电磁干扰，光/电/无线转换看具体设备。集线器/中继器工作在物理层，对比特再生，不解析MAC/IP。

## 三、链路层 ★ 窗口、共享介质与帧

### 1. 可靠传输与窗口

设序号n位，发送窗Ws、接收窗Wr，常见模型要求 Ws+Wr≤2ⁿ。

| 协议 | 发送窗 | 接收窗 | 出错时 |
|---|---|---|---|
| 停止等待 | 1 | 1 | 当前帧超时重传 |
| GBN | ≤2ⁿ−1 | 1 | 累计确认，失序丢弃；回退重传缺帧及之后未确认帧 |
| SR（对称） | ≤2ⁿ⁻¹ | ≤2ⁿ⁻¹ | 可缓冲失序，选择性重传；非对称时按总窗约束 |

无误码、忽略ACK发送/处理时间、持续有数据、RTT仅为往返传播时，设帧发送时延T=L/R：

$$U=\min(1,\frac{W_sT}{T+RTT}),\quad S=RU,\quad W_{连续}=\left\lceil\frac{T+RTT}{T}\right\rceil$$

利用率分母是从第一帧开始发送到第一个ACK返回，分子是窗口内连续发帧耗时；超过100%封顶。窗口反求序号位数要再套具体协议约束。

典型题：6位序号→GBN63、对称SR32。课中100Mb/s、1500B帧、低轨单向3.667ms，T=0.12ms，GBN可达到100Mb/s、SR约51.52Mb/s；高轨单向240ms时约1.575Mb/s、0.8Mb/s。高度增加未改变题设香农容量，但影响有效速率。

2025卫星题：200kb/s，单向传播0.24s，4000B发送0.16s，主要瓶颈模型端到端至少约0.40s；1500B帧发送0.06s，ACK循环0.54s，要求U≥80% → Ws≥8，GBN序号≥4位。

### 2. CSMA/CD、CSMA/CA

| 对比 | CSMA/CD（经典共享半双工以太网） | CSMA/CA（无线） |
|---|---|---|
| 方法 | 先听后发、边发边听、冲突停发、随机重发 | 载波监听、帧间间隔、退避与ACK，按题可用RTS/CTS |
| 为什么 | 最坏碰撞消息要往返回来 | 发送端难可靠检测空中冲突，存在隐藏站 |
| 关键间隔 | 争用期=2τ（最远单程传播及中间设备延迟） | SIFS优先于DIFS，NAV是虚拟载波监听预约的剩余时间 |
| 常考 | 发送完整最短帧前必须仍能观察最坏碰撞 | RTS→SIFS→CTS→SIFS→DATA→SIFS→ACK |

- 最小帧长 Lmin/R≥2τ；距离题先列 2d/v+双向设备时延≤发送时间。10Mb/s的64B帧是51.2µs；100Mb/s则5.12µs。高带宽下相同最短帧允许的冲突域直径更小。
- 2022例：100Mb/s、64B、v=2×10⁸m/s、Hub单向1.51µs → 最远两端线路总长≤210m。不把交换机隔开的链路并入相同冲突域。
- 第i次冲突退避随机整数r∈[0,2^min(i,10)−1]，等待r×争用期；连续16次冲突则放弃该帧。注意题问的是冲突次数还是已经尝试过的次数。
- CSMA/CA：开始发送通常先保证空闲DIFS，忙时冻结退避计数，重新连续空闲DIFS后继续剩余计数，不把未用完的计数直接重抽。老师用“社恐”比喻发送前确认周围安静。
- NAV从**当前收到的预约帧结束**算到被预约交互完成，不含当前帧本身；2024例收到CTS后的NAV=28+296+28+2=354µs。

### 3. 帧格式、交换机与AP

★ 以太网MAC帧口诀 **662N4，收发协数据验**：目的MAC6B、源MAC6B、类型/长度2B、数据46～1500B、FCS4B。典型首部14B、尾部4B，共64～1518B（无VLAN等附加字段；前导码与帧间隙另论）。IP包40B则数据字段填6B，IP总长仍为40B。目的MAC全1表示链路广播。

802.11基本数据帧：帧控制2B、持续期2B、地址1～3各6B、序号控制2B、可选地址4 6B、帧体、FCS4B；三地址基础首部24B，四地址基本首部30B，教材图示帧体0～2312B。

| 无线方向、To DS/From DS | 地址1、地址2、地址3 | 课程口诀 |
|---|---|---|
| 站→AP：1/0 | AP、原始链路源、二层交付目的 | 中起止 |
| AP→站：0/1 | 二层交付目的、AP、原始链路源 | 止中起 |

跨网时“止”可能是本地网关，不能填最终外网主机的MAC。AP是二层中转，未改原始链路源/目的；从无线转有线时重新封装相应帧。2022例H4首次DHCP广播上行三地址(AP,H4,FF…FF)，下行给无线站为(FF…FF,AP,H4)。

交换机每帧三步：①学源MAC→端口（刷新老化计时）；②查目的，已知且不同端口则定向转发，同端口则过滤，未知单播/广播则除入口外泛洪；③下一个事件前删除已超时表项。**即使帧被过滤也先学习源；仅收到帧的主机不会因此被交换机学习。**

集线器所有端口同冲突域，交换机端口分割冲突域（全双工不发生经典共享媒介冲突），同一VLAN仍通常一个广播域；路由器每侧隔离普通二层广播域。

## 四、网络层 ★ 地址、分片和实际转发

### 1. CIDR与路由选择

IP32位，/n表示n位网络前缀，普通子网地址数2^(32−n)，可用数减2（网络地址、广播地址）；再扣除网关、固定地址等已占用项。主机用自身掩码分别与本机/目标IP按位与，前缀相同则正常直接交付，异网则按路由表找下一跳。

| /n | 末字节掩码 | 块大小、普通可分配数 |
|---|---:|---|
| /24 | 0 | 256、254 |
| /25 | 128 | 128、126 |
| /26 | 192 | 64、62 |
| /27 | 224 | 32、30 |
| /28 | 240 | 16、14 |
| /29 | 248 | 8、6 |
| /30 | 252 | 4、2 |

变长子网先确定每块容量（2^h−2≥H），考虑已知位置再分较大块，保证边界对齐、不重叠。老师的二叉树“左0右1”：2025已知管理区10.10.10.33/26，管理.0/26，作业.64/26，生活.128/25。2018剩余地址：126−80个主机−1个网关=45。

同长度、相邻且对齐的前缀能在同下一跳等条件下聚合；路由查表取**最长匹配**而非表中第一条，/0默认路由是兜底。下一跳地址与最终目的IP不同概念。TTL>0才可继续正常转发，经过m台路由器应至少初始m+1；TTL不是OSPF权值。普通以太网广播不跨路由器；远端定向广播看条件。

### 2. DHCP 四步入网、ARP

DHCP应用层，UDP服务器67/客户端68。分配IP、掩码、网关、DNS、租期等。DORA求职口诀：海投简历→公司发offer→宣布选择→正式签约。

| 初次入网报文 | UDP方向 | 课例IP源→目的（服务器IP=S） |
|---|---|---|
| Discover | 68→67 | 0.0.0.0→255.255.255.255 |
| Offer | 67→68 | S→255.255.255.255 |
| Request | 68→67 | 0.0.0.0→255.255.255.255 |
| ACK | 67→68 | S→255.255.255.255 |

课例Discover/Request为MAC广播；Offer/ACK采用MAC单播给客户端（实际也可能广播或IP单播，**按题设**）。Request宣告所选地址让其他服务器收回offer。逐层过滤：链路层谁收到先看MAC，网络层谁接收看目的IP，UDP是否交应用看目的端口；IP广播不意味着可以越过单播MAC过滤。

ARP：IP→当前链路MAC，缓存未命中才查。请求广播、应答通常单播；请求内含发送者IP/MAC和目标IP，目标MAC未知，接收者可学习发送者映射。ARP直接装入以太网帧，常用类型0806H，不额外套IP或UDP。异网查网关IP的MAC而非远端MAC；同网默认网关错误可能仍能通信。

### 3. NAT/PAT 与 IPv4首部

私网范围10/8、172.16/12、192.168/16。通常内网访问公网：出网改源IP、必要时源端口；回程查映射改目的IP/必要时目的端口。公网映射端口不等于主机绑定端口。NAT需相应处理校验和；若只问**IP首部**字段，不能把TCP/UDP端口列进去。

| 字段 | 单位/常考含义 |
|---|---|
| IPv4 IHL | 4B单位，5→20B |
| Total Length | 1B单位，16bit最大65535B，IP头+数据 |
| Fragment Offset | 8B单位，相对原始IP数据起点 |
| ID | 同一原始数据报各分片共享（结合源、目的、协议识别） |
| DF/MF | DF限制是否可分片；MF=1原始数据后面还有，0为末片 |
| TTL/Checksum | 逐跳更新；IPv4校验和只覆盖首部 |
| Protocol | ICMP=1、TCP=6、UDP=17、OSPF=89 |

★ **418首总片**，4/1/8三个单位。IPv4 EtherType0800H、ARP0806H；不要混成IP Protocol或端口。

### 4. MTU、MSS、分段、分片、填充

| 层次 | 长度规则（无选项时） |
|---|---|
| UDP | 固定8B首部，Length=8+净荷；IPv4头20B时最大UDP净荷65507B |
| TCP | Data Offset×4=首部长，最低20B。MSS仅数据部分；以太网MTU1500时典型MSS1460 |
| IPv4 | IHL×4是首部长，IP总长≤MTU；超过且允许分片时每片加独立IP头 |
| 以太网 | 数据46～1500B；IP包短于46B则帧层填充，IP头的长度不变 |

分片模型：各片首部h，MTU=M，非末片最大IP净荷=8·floor((M−h)/8)。每片偏移=该片原始IP数据起点/8，MF看**原始**数据是否结束；最后一片不一定要8B对齐。中间路由器再分片逐片处理、不先重组；若原片MF=1，拆出的最后一片仍MF=1。

- 3200B应用消息经UDP→3208B IP数据。MTU1500、头20B：净荷1480/1480/248，偏移0/185/370，总长1500/1500/268。只第一片有原UDP头。
- 若从原包直接按800 MTU切：净荷776×4+104，偏移0/97/194/291/388，每片加20B。已有1500 MTU片再切则偏移0/97、185/282、370，不能把两方案混用。
- 2018真题：原1500B IP包→MTU800，净荷776/704，总长796/724，偏移0/97。MF1/0。
- 若3200B HTTP消息直接走TCP、MSS1460：1460/1460/280；IP总长1500/1500/320，帧1518/1518/338，应用头只一份。TCP分段并不保证沿途任何条件下都不分片。

## 五、传输层 ★ TCP账本与窗口

UDP无连接、保留数据报边界、不提供TCP式可靠字节流；TCP面向连接、提供可靠有序的字节流服务。端口区分进程，发送/接收方向改变时端口相应调换；TCP连接看双方IP与端口的组合。

| TCP字段 | 单位和关键点 |
|---|---|
| SEQ | 字节编号，本段首个数据字节的序号 |
| ack | 下一期望收到的字节序号（累计确认），ACK标志为1时有效 |
| SYN/FIN | 无数据也各占1个序号，纯ACK不占 |
| Data Offset | 4B单位；TCP数据长=IP总长−IP头长−TCP头长 |
| Window | 接收方通告窗口rwnd，以B计，不是cwnd或MSS个数 |

握手：C→S(SYN=1,ACK=0,seq=x)，S→C(SYN=1,ACK=1,seq=y,ack=x+1)，C→S(ACK=1,seq=x+1,ack=y+1)。第三次可携带数据；发送L字节后本方向序号增加L。

挥手：C FIN(seq=u)→S ACK(ack=u+1)→S FIN(seq=v)→C ACK(ack=v+1)。主动端发最后ACK后TIME-WAIT等2MSL（收到重传FIN按规则重计）；被动端收到最后ACK可关闭。立即完成中间两次时，从发首个FIN到被动端收最后ACK约1.5RTT，主动端完整关闭约1RTT+2MSL（按题理想时序）。

### 窗口题：不要直接按RTT翻倍

- rwnd受接收缓存约束；cwnd受网络拥塞控制；发送窗口上限=min(rwnd,cwnd)；还能新发多少还要扣除已发未确认量。
- 课程初始cwnd=1MSS、每段有新ACK的慢开始模型：每次确认新段增长1MSS，全部满窗发完并确认才会每RTT约翻倍。拥塞避免典型每RTT约增1MSS。老师的健身类比：初期逐步增量、达到门限后放缓；超时通常将门限调整到原拥塞时的一半并从初始窗开始（算法与题设另论）。
- ★ 2016题20KB接收缓存，从1MSS开始，MSS=1KB，阈值32KB。每轮发1、2、4、8、5段；第8个ACK刚收到时rwnd=12KB/cwnd=9KB/发送窗上限9KB；5RTT后rwnd=0/cwnd=21KB。初始SEQ100，下一待发SEQ=100+1+20×1024=20581；RTT200ms时数据阶段平均20KB/s，服务器释放最短300ms。
- 2012题拆首部：可变IP/TCP首部长先定位，识别SYN/ACK配对；接收数据量=最高累计ACK−数据起始SEQ（排除控制占用），例D6H−C6H=10H=16B。Window 16D0H=5840B；同一报文TTL从40H→31H，经过15路由器。

## 六、应用层 ★ 将碎片记成协议对照

| 协议 | 传输层及熟知端口 | 重点 |
|---|---|---|
| DNS | UDP/TCP 53 | 域名→IP；普通查询常UDP，TCP有相应使用条件 |
| HTTP | TCP 80（传统模型） | GET/POST，请求与回应，持续/流水线 |
| FTP | TCP 21控制、主动模式20数据 | 两条独立TCP连接，控制可持续，数据按传输建立 |
| SMTP | TCP 25 | 发送/推邮件 |
| POP3 | TCP 110 | 提取/拉邮件 |
| DHCP | UDP 67/68 | IP配置，四报文 |
| RIP | UDP 520 | 封装在UDP中 |
| BGP | TCP 179 | 封装在TCP中 |
| OSPF | 直接IP（Protocol=89） | 不用端口 |
| ICMP | 直接IP（Protocol=1） | 差错报告等控制消息 |
| ARP | 直接以太网帧 | 当前链路下一跳IP→MAC |

DNS域名树是行政/逻辑关系，并非物理链路拓扑。递归查询如“跑腿”替请求者最终查到答案；迭代如“指路”，给下一级服务器线索。通常主机→本地DNS递归，本地DNS再通过缓存或根→顶级→权限服务器迭代。老师的宿舍类比：房号组织层次不等于实际去问的物理路径。

FTP主动/被动指数据连接由哪一方启动，控制连接均客户端→服务端21。主动数据服务端传统端口20→客户端所告端口；被动客户端连接服务端告知的临时数据端口。两条TCP连接的握手、SEQ、ACK独立；2023题数据连接起始SYN序号100、已收18000B后FIN确认18102（含SYN、FIN各1）。

电子邮件SMTP推送、POP3拉取，MIME扩展邮件内容类型；不要把应用层行为当传输层功能。

### HTTP 四种计算方式（老师重点）

只有一个HTML且无后续引用：初始未建连2RTT。若HTML引用k>0个小资源，忽略传输/处理时延，连接建立1RTT、请求返回1RTT：

| 模式 | 从完全未建连开始 | 从首页GET已发出开始 |
|---|---:|---:|
| 非持续、串行 | 2(k+1) | 2k+1 |
| 非持续、足够并行 | 4 | 3 |
| 持续、非流水线 | k+2 | k+1 |
| 持续、流水线 | 3 | 2 |

单位为RTT。必须先取得HTML才知道后续资源URL。2011五图持续非流水线、从首页GET起=6RTT。只问网页到齐不计TCP完整关连接；大文件按给出的带宽另外算发送时间。HTTP请求行/状态行、首部、空行、可选实体与TCP段首部不同。

## 七、路由协议 ★ 把算法、封装、陷阱一起记

| 特征 | RIP | OSPF | BGP |
|---|---|---|---|
| 范围 | AS内部 | AS内部 | AS之间（含内部传播BGP路由） |
| 算法/信息 | 距离向量，邻居距离 | 链路状态，区域拓扑+Dijkstra | 路径向量，AS路径、策略 |
| 封装 | UDP520 | IP协议89 | TCP179 |
| 度量/选择 | 跳数，16不可达 | 链路代价 | 策略和路径属性 |

- RIP课堂模型：直连距离1，向邻居候选=对方距离+1，16表示不可达。收到当前下一跳的更新要更新相应代价（包括变差）；其他候选择优。好消息按BFS层层扩展，同步每30s一轮、首次在t=0交换时，与最初广告者相距m条路由器邻接边的路由器通常在(m−1)×30s学到该信息；看题规定发报轮次。坏消息可能“踢皮球”计数到16，画每轮旧表→新表，不把尚未传播的新信息提前用上。
- OSPF泛洪链路状态通告、构建对应拓扑，Dijkstra每轮选未确定中最近节点并松弛邻边；边权影响最短路而**不**是IP TTL扣减值。OSPF区域等题按拓扑及通告范围理解。
- BGP在AS之间传播可达路径（eBGP/iBGP）；Open、Update、Keepalive、Notification。课堂2024题简化口诀“一偏二短三土四老”：优先本地偏好、再短AS_PATH、再内部代价、最后按题给的ID等决胜规则。真实BGP属性和策略更复杂，不把这四项当作所有实现的完整算法。

## 八、最后10分钟：高频误区回忆清单

1. 先画链路/子网与设备接口；源/目的MAC逐跳，IP一般端到端，NAT单独处理；查询的是下一跳而非远端MAC。
2. DHCP的67/68、DNS的53、FTP的21/20，以及ARP直接链路封装、OSPF直接IP。
3. 发送和传播时延分别用L/R、d/v；去/回几段按时间线；利用率封顶、窗口向上取整。
4. “662N4”“418首总片”“中起止/止中起”；分片的原偏移、MF与填充，TCP的MSS只算数据。
5. 子网网络/广播不可分配，网关也占地址；/0最后匹配；TTL按转发次数。
6. CSMA/CD最短帧≥往返延时；交换机先学源再查目的；CSMA/CA的DIFS、SIFS和NAV从哪个时刻起计。
7. TCP SYN/FIN各耗1；ack下一期待；rwnd与cwnd取小，逐ACK算慢开始，不保证每轮翻倍。
8. HTTP先数首页与引用资源、再确认计时起点；RIP看每轮旧信息，OSPF看加权拓扑，BGP看题给策略顺序。
